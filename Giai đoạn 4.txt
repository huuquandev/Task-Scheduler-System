  Review Giai đoạn 3 — Scheduler Engine

  Những gì đã làm đúng

  Kiến trúc tốt:
  - ISchedulerService đặt đúng trong Application layer — Application không biết Hangfire cụ thể, đúng Clean Architecture
  - ITaskExecutionService tách riêng đúng theo hướng dẫn — cả Hangfire (TaskJob) và manual trigger (TriggerTaskHandler) đều dùng chung, không lặp code
  - HangfireSchedulerService implement đúng: AddOrUpdate cho schedule/reschedule, RemoveIfExists cho unschedule
  - TaskJob đóng vai trò wrapper mỏng để Hangfire resolve DI — đúng pattern
  - ActiveTaskHandler và ResumeTaskHandler đều kết nối với ISchedulerService sau khi save
  - Registration trong Program.cs đủ: Hangfire + PostgreSql + HangfireServer + DI ISchedulerService và ITaskExecutionService

  ---
  Những vấn đề cần lưu ý

  1. CreateTaskHandler chưa gọi ISchedulerService.ScheduleTaskAsync

  Theo bảng trong giai đoạn 3, sau khi tạo task phải schedule ngay. Hiện tại CreateTaskHandler chỉ AddAsync rồi return — task được tạo nhưng không bao giờ được Hangfire biết đến.

  Tuy nhiên, đây có thể là chủ ý — task mới tạo có status Pending, phải qua ActiveTask mới được schedule. Nếu đây là thiết kế có chủ đích thì ổn, nhưng cần document rõ flow này.

  2. TaskExecutionService không gọi UpdateNextRunTime()

  Sau khi task chạy xong và MarkAsActive(), NextRunAt không được cập nhật. Nên gọi task.UpdateNextRunTime() trước khi UpdateAsync.

  3. ScheduleTaskAsync và RescheduleTaskAsync giống hệt nhau

  Cả hai đều gọi RecurringJob.AddOrUpdate với cùng logic. RescheduleTaskAsync hoàn toàn có thể delegate sang ScheduleTaskAsync hoặc bỏ hẳn một trong hai. Đây là code trùng lặp nhỏ nhưng nên dọn.

  4. TriggerTaskHandler không check status Active

  Hiện tại task có status bất kỳ (kể cả Failed, Paused) đều có thể bị trigger thủ công. Tùy business rule nhưng nên xem xét giới hạn chỉ Active hoặc Failed mới được trigger.

  5. Hangfire Dashboard chưa có auth

  app.UseHangfireDashboard("/hangfire") không có option nào — dashboard công khai, ai cũng truy cập được. Cần thêm DashboardOptions với authorization filter trước giai đoạn 4.

  Giai đoạn 4 — API Layer

  Đây là giai đoạn hoàn thiện phần presentation. Có 4 nhóm việc:

  4.1 — ExceptionHandlingMiddleware + chuẩn hóa response

  Hiện tại nếu handler throw ArgumentException hay InvalidOperationException, ASP.NET trả về 500 với stack trace — không chuẩn và lộ thông tin nội bộ.

  Cần làm:
  - Tạo ExceptionHandlingMiddleware bắt toàn bộ exception, map sang HTTP status code phù hợp (ArgumentException → 404, InvalidOperationException → 400, mọi thứ khác → 500)
  - Tạo ApiResponse<T> wrapper chuẩn hóa mọi response: { success, data, error, statusCode }
  - Mọi controller action trả về ApiResponse<T> thay vì trả trực tiếp

  4.2 — Hoàn thiện Controllers

  Kiểm tra lại xem đã có đủ các endpoint chưa:

  - POST /api/v1/tasks/{id}/resume — kích hoạt lại từ Paused
  - POST /api/v1/tasks/{id}/trigger — chạy thủ công
  - GET /api/v1/tasks/{id}/logs — lịch sử execution
  - GET /api/v1/dashboard — thống kê tổng quan

  4.3 — JWT Authentication

  - Cài Microsoft.AspNetCore.Authentication.JwtBearer
  - Tạo AuthController với POST /api/v1/auth/login (trả JWT token) và POST /api/v1/auth/register

  4.4 — Swagger hoàn thiện

  - Thêm XML doc comments cho request/response
  - Thêm JWT Bearer scheme vào AddSwaggerGen
  - Thêm response examples cho các endpoint chính

  Bước 4.2 — Setup JWT Authentication trong Program.cs

  appsettings.json đã có đủ Jwt section. TokenService đã implement. Chỉ cần thêm vào Program.cs.

  Thêm package (chạy trong terminal):
  dotnet add src/TaskScheduler.Api package Microsoft.AspNetCore.Authentication.JwtBearer

  Trong Program.cs, thêm 3 thứ:

  1. Using ở đầu file:
  using Microsoft.AspNetCore.Authentication.JwtBearer;
  using Microsoft.IdentityModel.Tokens;
  using System.Text;
  using TaskScheduler.Infrastructure.Services;

  2. Đăng ký services — thêm vào sau block // DI hiện tại:
  // Auth
  builder.Services.AddScoped<IUserRepository, UserRepository>();
  builder.Services.AddScoped<ITokenService, TokenService>();

  builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
      .AddJwtBearer(options =>
      {
          options.TokenValidationParameters = new TokenValidationParameters
          {
              ValidateIssuer = true,
              ValidateAudience = true,
              ValidateLifetime = true,
              ValidateIssuerSigningKey = true,
              ValidIssuer = builder.Configuration["Jwt:Issuer"],
              ValidAudience = builder.Configuration["Jwt:Audience"],
              IssuerSigningKey = new SymmetricSecurityKey(
                  Encoding.UTF8.GetBytes(builder.Configuration["Jwt:Secret"]!))
          };
      });

  3. Trong pipeline — thêm UseAuthentication trước UseAuthorization (thứ tự này quan trọng):

  app.UseAuthorization();

  Bước 4.3 — Tạo Auth Commands/Handlers trong Application layer

  Mục tiêu: AuthController không chứa business logic — tất cả đi qua MediatR.

  Tạo 2 file command + handler:

  File 1: src/TaskScheduler.Application/Auth/Commands/Login/LoginCommand.cs

  using MediatR;
  using TaskScheduler.Application.Auth.DTOs;

  namespace TaskScheduler.Application.Auth.Commands.Login
  {
      public record LoginCommand(string Username, string Password) : IRequest<AuthResponse>;
  }

  File 2: src/TaskScheduler.Application/Auth/Commands/Login/LoginHandler.cs

  using MediatR;
  using TaskScheduler.Application.Auth.DTOs;
  using TaskScheduler.Application.Interfaces;

  namespace TaskScheduler.Application.Auth.Commands.Login
  {
      public class LoginHandler : IRequestHandler<LoginCommand, AuthResponse>
      {
          private readonly IUserRepository _userRepository;
          private readonly ITokenService _tokenService;

          public LoginHandler(IUserRepository userRepository, ITokenService tokenService)
          {
              _userRepository = userRepository;
              _tokenService = tokenService;
          }

          public async Task<AuthResponse> Handle(LoginCommand request, CancellationToken cancellationToken)
          {
              var user = await _userRepository.GetByUsernameAsync(request.Username);
              if (user == null || !_tokenService.VerifyPassword(request.Password, user.PasswordHash))
                  throw new UnauthorizedAccessException("Invalid username or password.");

              if (!user.IsActive)
                  throw new UnauthorizedAccessException("Account is disabled.");

              var token = _tokenService.GenerateJwtToken(user);

              return new AuthResponse
              {
                  Token = token,
                  Username = user.Username,
                  Email = user.Email
              };
          }
      }
  }

  File 3: src/TaskScheduler.Application/Auth/Commands/Register/RegisterCommand.cs

  using MediatR;

  namespace TaskScheduler.Application.Auth.Commands.Register
  {
      public record RegisterCommand(string Username, string Email, string Password) : IRequest<Guid>;
  }

  File 4: src/TaskScheduler.Application/Auth/Commands/Register/RegisterHandler.cs

  using MediatR;
  using TaskScheduler.Application.Interfaces;
  using TaskScheduler.Domain.Entities;

  namespace TaskScheduler.Application.Auth.Commands.Register
  {
      public class RegisterHandler : IRequestHandler<RegisterCommand, Guid>
      {
          private readonly IUserRepository _userRepository;
          private readonly ITokenService _tokenService;

          public RegisterHandler(IUserRepository userRepository, ITokenService tokenService)
          {
              _userRepository = userRepository;
              _tokenService = tokenService;
          }

          public async Task<Guid> Handle(RegisterCommand request, CancellationToken cancellationToken)
          {
              if (await _userRepository.UsernameExistsAsync(request.Username))
                  throw new InvalidOperationException("Username already exists.");

              if (await _userRepository.EmailExistsAsync(request.Email))
                  throw new InvalidOperationException("Email already exists.");

              var user = new User
              {
                  Id = Guid.NewGuid(),
                  Username = request.Username,
                  Email = request.Email,
                  PasswordHash = _tokenService.HashPassword(request.Password),
                  CreatedAt = DateTime.UtcNow,
                  IsActive = true
              };

              await _userRepository.AddAsync(user);

              // UserRepository.AddAsync không gọi SaveChanges — cần inject DbContext hoặc Unit of Work
              // Xem note bên dưới
              return user.Id;
          }
      }
  }

  ▎ Note về SaveChanges: Nhìn vào UserRepository.AddAsync — nó chỉ gọi _context.Users.AddAsync(user) mà không có SaveChangesAsync(). Có 2 cách xử lý:
  ▎ - Thêm await _context.SaveChangesAsync() vào cuối UserRepository.AddAsync() — đơn giản nhất
  ▎ - Hoặc inject ApplicationDbContext trực tiếp vào handler và gọi SaveChangesAsync() tại đó
  ▎
  ▎ Chọn cách 1: mở UserRepository.cs, sửa AddAsync:
  ▎ public async Task AddAsync(User user)
  ▎ {
  ▎     await _context.Users.AddAsync(user);
  ▎     await _context.SaveChangesAsync();
  ▎ }

  Bước 4.6 — Xử lý UnauthorizedAccessException trong Middleware

  ExceptionHandlingMiddleware hiện chưa map UnauthorizedAccessException. Mở ExceptionHandlingMiddleware.cs, thêm case vào switch expression:

  var response = exception switch
  {
      UnauthorizedAccessException => ApiResponse<object>.FailureResponse(
          exception.Message,
          StatusCodes.Status401Unauthorized),

      ArgumentException => ApiResponse<object>.FailureResponse(
          exception.Message,
          StatusCodes.Status400BadRequest),

      InvalidOperationException => ApiResponse<object>.FailureResponse(
          exception.Message,
          StatusCodes.Status400BadRequest),

      KeyNotFoundException => ApiResponse<object>.FailureResponse(
          exception.Message,
          StatusCodes.Status404NotFound),

      _ => ApiResponse<object>.FailureResponse(
          "An internal server error occurred",
          StatusCodes.Status500InternalServerError)
  };

  ▎ Cũng cần fix ExceptionHandlingMiddleware.cs line 63: return context.Response.WriteAsJsonAsync(response) — method này trả về Task nhưng đang bị return trong method void. Sửa thành await:
  ▎ await context.Response.WriteAsJsonAsync(response);

  Bước 4.7 — Hoàn thiện Swagger với JWT Bearer

  Mở Program.cs, thay block AddSwaggerGen hiện tại:

  using Microsoft.OpenApi.Models;

  builder.Services.AddSwaggerGen(c =>
  {
      c.EnableAnnotations();

      c.AddSecurityDefinition("Bearer", new OpenApiSecurityScheme
      {
          Name = "Authorization",
          Type = SecuritySchemeType.Http,
          Scheme = "Bearer",
          BearerFormat = "JWT",
          In = ParameterLocation.Header,
          Description = "Nhập JWT token. Ví dụ: Bearer {token}"
      });

      c.AddSecurityRequirement(new OpenApiSecurityRequirement
      {
          {
              new OpenApiSecurityScheme
              {
                  Reference = new OpenApiReference
                  {
                      Type = ReferenceType.SecurityScheme,
                      Id = "Bearer"
                  }
              },
              Array.Empty<string>()
          }
      });
  });

  Sau bước này Swagger UI sẽ có nút Authorize ở góc trên phải. Bạn login lấy token, paste vào đó, rồi test tất cả endpoint có [Authorize] ngay trên browser.
