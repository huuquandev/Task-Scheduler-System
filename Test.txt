  PHẦN 1 — Hoàn thiện Application Tests (làm trước)

  1.1 Fix bug trong DeleteTaskCommandHandlerTests

  3 test cuối đang không await handler — assert chạy trước khi handler được gọi. Sửa pattern từ:
  var action = () => handler.Handle(command, CancellationToken.None);
  existingTask.IsDeleted.Should().BeTrue(); // ← luôn false vì handler chưa chạy
  Thành:
  await handler.Handle(command, CancellationToken.None);
  existingTask.IsDeleted.Should().BeTrue();

  1.2 PauseTaskCommandHandlerTests — đang rỗng

  Test 2 — Task không ở trạng thái Active:

  1.5 ValidationBehaviorTests — quan trọng, đang rỗng

  Đây là test cho pipeline behavior — cần dùng generic:

  Setup: Tạo validator giả bằng Moq hoặc dùng validator thật (CreateTaskCommandValidator)

  Test 1 — Command hợp lệ:
    → RequestHandlerDelegate được gọi 1 lần (handler chạy bình thường)

  Test 2 — Command không hợp lệ:
    → Throw ValidationException
    → RequestHandlerDelegate KHÔNG được gọi (handler bị chặn)

  Test 3 — Không có validator đăng ký:
    → RequestHandlerDelegate vẫn được gọi (pass-through)

  Cách tạo mock delegate trong Moq:
  var nextCalled = false;
  RequestHandlerDelegate<Guid> next = () => {
      nextCalled = true;
      return Task.FromResult(Guid.NewGuid());
  };

  1.6 Validators — đã có file, cần content

  CreateTaskCommandValidatorTests và UpdateTaskCommandValidatorTests — dùng FluentValidation's TestValidate:

  // Không cần mock gì cả
  var validator = new CreateTaskCommandValidator();
  var result = validator.TestValidate(command);

  // Assert
  result.ShouldHaveValidationErrorFor(x => x.Name);
  result.ShouldNotHaveValidationErrorFor(x => x.CronExpression);

  Các case cần test:
  - Name = "" / " " / null → lỗi
  - Name > 200 ký tự → lỗi
  - CronExpression = "abc xyz" → lỗi (validator gọi CronExpression.Create() → throw)
  - MaxRetries < 0 → lỗi
  - Tất cả hợp lệ → không có lỗi nào

  PHẦN 2 — Infrastructure Tests (làm sau Application)

  2.1 Setup DbContextFactory trước — mọi test đều cần

  DbContextFactory.cs đang rỗng — đây là nền móng. Cần implement bằng SQLite in-memory:

  Bước 1: Thêm package vào Infrastructure.Tests project:
    dotnet add Tests/TaskScheduler.Infrastructure.Tests package Microsoft.EntityFrameworkCore.Sqlite

  Bước 2: Implement DbContextFactory tạo DbContext với SQLite:
    - Mỗi lần gọi Create() → tạo DbContext mới với database name ngẫu nhiên
    - Gọi EnsureCreated() để tạo schema
    - Dispose DbContext sau mỗi test (implement IDisposable)

  Bước 3: BaseInfrastructureTest kế thừa, mỗi test có DbContext sạch riêng

  Quy tắc vàng của Repository tests: Dùng 2 DbContext khác nhau:
  DbContext #1 → dùng để seed data (setup)
  DbContext #2 → dùng để assert (query lại từ DB)
  Lý do: EF Core cache entity trong DbContext — nếu dùng cùng 1 context, assert sẽ lấy từ cache, không phải từ DB thật → test có thể pass dù DB bị sai.

  2.2 TaskRepositoryTests — ưu tiên cao nhất

  Sau khi có DbContextFactory, implement theo thứ tự:

  AddAsync:
  → Seed 1 task → query lại bằng context #2 → task phải tồn tại trong DB

  GetByIdAsync — found:
  → Seed → GetById → trả về đúng task

  GetByIdAsync — not found:
  → GetById với Guid không tồn tại → trả về null

  GetByIdAsync — soft deleted:
  → Seed task với IsDeleted=true → GetById → trả về null (nếu repo filter)

  UpdateAsync:
  → Seed → MarkAsFailed() → UpdateAsync → query lại → status = Failed trong DB

  GetPagedAsync — pagination:
  → Seed 10 tasks → GetPaged(page=1, size=5) → trả về 5 tasks
  → GetPaged(page=2, size=5) → trả về 5 tasks tiếp theo

  GetPagedAsync — filter by status:
  → Seed 3 Active + 2 Paused → filter Active → chỉ trả về 3

  2.3 TokenServiceTests

  Không cần DbContext, chỉ cần config JWT. Setup:
  Tạo IConfiguration giả với Jwt:Secret, Jwt:Issuer, Jwt:Audience, Jwt:ExpiryMinutes
  Khởi tạo TokenService(config)

  Các test:
  HashPassword → result khác plaintext
  VerifyPassword → đúng password = true, sai = false
  GenerateJwtToken → decode được bằng JwtSecurityTokenHandler, chứa claim "username"
  GenerateJwtToken → token có expiry sau thời gian hiện tại

  2.4 UserRepositoryTests và ExecutionLogRepositoryTests

  Pattern giống TaskRepository nhưng đơn giản hơn:
  UserRepository: GetByUsernameAsync, UsernameExistsAsync, EmailExistsAsync, AddAsync
  ExecutionLogRepository: GetByTaskIdAsync (trả về logs của 1 task), AddAsync

  2.5 HangfireSchedulerServiceTests — làm cuối, tricky nhất

  Dùng Hangfire's in-memory storage thay vì PostgreSQL:
  Đăng ký GlobalConfiguration.Configuration.UseMemoryStorage()
  Gọi ScheduleTaskAsync → kiểm tra job có trong storage không
  Gọi UnscheduleTaskAsync → job không còn trong storage

  Nếu RecurringJob.AddOrUpdate là static và khó test, refactor HangfireSchedulerService để nhận IRecurringJobManager qua constructor injection thay vì gọi static trực tiếp — interface này Hangfire đã
  cung cấp sẵn, mock được.

  3.3 Các test cần có

  Auth flow — test đầu tiên vì mọi test khác cần token:
  POST /api/v1/auth/register → 200 OK + Guid
  POST /api/v1/auth/register lần 2 cùng username → 400 Bad Request
  POST /api/v1/auth/login đúng → 200 OK + JWT token
  POST /api/v1/auth/login sai password → 401 Unauthorized

  Protected endpoints:
  GET /api/v1/tasks không có token → 401
  GET /api/v1/tasks có token → 200

  Task CRUD full flow:
  Register → Login → dùng token:
  POST /api/v1/tasks (valid) → 200 + taskId
  POST /api/v1/tasks (cron sai) → 400
  GET /api/v1/tasks/{id} (id vừa tạo) → 200 + task data
  GET /api/v1/tasks/{id} (id không tồn tại) → 404
  PUT /api/v1/tasks/{id} → 200
  DELETE /api/v1/tasks/{id} → 200

  Helper pattern — tái sử dụng login:
  // Tạo method dùng chung trong base test class
  private async Task<string> GetAuthTokenAsync()
  {
      // Register + Login → trả về token string
      // Gán vào HttpClient.DefaultRequestHeaders.Authorization
  }
